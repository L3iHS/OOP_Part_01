# Лабораторная работа 2 — класс String

Семейство A, вариант 2. Строковый класс с ручным управлением динамическим массивом символов.

## Требования

- C++20, CMake 3.16+ и не менее 12 тестов Google Test.
- Память выделяется через `new[]` и освобождается через `delete[]`.
- RAII, глубокое копирование, перемещение за O(1) с обнулением источника и присваивание через copy-and-swap.
- Добавление символа, дописывание строки, поиск подстроки и вывод.
- Минимальная начальная ёмкость — 1; заполненный буфер увеличивается вдвое. Под завершающий `\0` выделяется дополнительный байт.
- Использование `std::string`, `std::vector`, `std::array` и умных указателей запрещено.
- Проверка граничных случаев и ошибок работы с памятью.

## Вариант 2

Метод `String remove_char(char c) const` возвращает новую строку без всех вхождений символа `c`, сохраняя порядок остальных символов и исходную строку.

Примеры: `"banana"` без `'a'` превращается в `"bnn"`; `"abc"` без `'x'` остаётся `"abc"`.

## Интерфейс и поведение

| Метод | Назначение |
|---|---|
| `String()` | Пустая строка с ёмкостью 1 |
| `String(const char*)` | Копия C-строки; `nullptr` трактуется как пустая строка |
| `String(const String&)` | Глубокое копирование в отдельный буфер |
| `String(String&&)` | Передача буфера за O(1) с обнулением источника |
| `operator=(String)` | Копирующее и перемещающее присваивание через copy-and-swap |
| `swap` | Обмен полями без копирования символов |
| `size`, `capacity`, `c_str` | Чтение длины, ёмкости и символов |
| `push_back` | Добавление одного символа |
| `append` | Дописывание C-строки или объекта `String` |
| `find` | Позиция первого вхождения подстроки или `String::npos` |
| `print` | Вывод символов в переданный поток |
| `remove_char` | Новая строка без заданного символа; исходная сохраняется |

Под буфер выделяется `capacity_ + 1` байт; `data_[size_]` содержит `\0`. Если места недостаточно, ёмкость удваивается до нужного размера. Размеры проверяются на переполнение перед увеличением.

После перемещения источник имеет размер 0, ёмкость 0 и нулевой внутренний указатель. Его можно уничтожать, читать, копировать, присваивать и снова наполнять. `c_str()` для него возвращает пустую C-строку.

`append` поддерживает дописывание строки самой к себе и указатель внутрь своего буфера. Пустое дополнение, включая `nullptr`, ничего не меняет. Пустая подстрока при поиске находится на позиции 0.

Операции работают с элементами `char`, то есть с байтами. C-строка на входе заканчивается первым `\0`. При добавлении через `push_back` внутренний нулевой байт учитывается в размере; копирование, `append(String)`, `find(String)`, `print` и `remove_char` его сохраняют или обрабатывают как обычный элемент. Вывод через `c_str()` средствами для C-строк заканчивается на первом нулевом байте.

Указатель из `c_str()` предоставляет чтение существующего буфера. При перераспределении или освобождении этого буфера ранее полученный указатель становится недействительным.

## Файлы

- `src/string.hpp` — интерфейс класса.
- `src/string.cpp` — реализация класса.

## Сборка и запуск

Команды выполняются из каталога лабораторной работы:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/lab2
ctest --test-dir build --output-on-failure
```

Google Test 1.17.0 загружается при первой настройке сборки. Для сборки только примера используйте `-DBUILD_TESTING=OFF`.

Для CMake 3.16–3.19 запускайте CTest из каталога `build` командой `ctest --output-on-failure`.

Пункт меню удаления символа показывает новую строку, сохраняя исходную. Пункт демонстрации создаёт независимую копию, добавляет к ней `!` и перемещает её в другой объект.

## Проверка памяти

Для GCC и Clang доступна отдельная сборка с AddressSanitizer и UBSan:

```sh
cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build-sanitize
ctest --test-dir build-sanitize --output-on-failure
```

В macOS утечки также можно проверить системной утилитой на всём наборе тестов:

```sh
leaks --atExit -- ./build/lab2_tests
```
